# Stage 4 — Human Punch-Out Verification Evidence (mocked/offline)

Generated by `scripts/run_punch_out_evidence.py` against `MockClient` — **no
model calls, no network**.  This is mocked evidence, distinct from the live
workflow punch-out record in `evidence/punch_out.md` and `evidence/runs/`.
Regenerate with:

```bash
.venv/bin/python scripts/run_punch_out_evidence.py
```

## Authorization model under test

A punch-out halts the run (`punch_out_required`, exit 2) and persists a
pending decision `punch_outs/<punch_out_id>.pending.json` bound to the run,
step, reason and artifact `context_hash`.  Resume is authorized only by an
immutable HMAC-SHA256-signed `*.decision.json` written by
`runner.py --decide`, whose approver must be in
`human_approvals.approvers` (`config/workflow.yaml`); the key comes from
`FICTIONFORGE_APPROVAL_KEY` or `config/approval_signing.key` (auto-generated
0600, never logged).  `deny` decisions move the run to terminal
`human_denied`.  Security halts (`artifact_tampered`,
`gate_approval_invalid`, `unknown`) are never approvable — enforced at
`--decide` and re-checked at `resume()`.  Approver identity is attested, not
authenticated: the boundary is key possession + allowlist membership (see
docs/workflow.md §5 and §10).

## Files

| File | Contents |
|---|---|
| `test_results.json` | Executed scenario matrix: trigger, expected vs actual outcome, pass/fail, audit event references, code/config hash, timestamp |
| `execution_trace.jsonl` | Real audit events captured from the mocked run directories (punch_out, human_decision, resume, step events) |
| `approval_case.json` | Pending + signed approve decision + final records for the run that resumed to `completed` |
| `denial_case.json` | Pending + signed deny decision + terminal `human_denied` summary for the denied run |
| `runs/approval_run/` | Captured run directory (artifacts, gates, audit.jsonl, punch_outs/, summary.json) |
| `runs/denial_run/` | Captured run directory for the denied case |
